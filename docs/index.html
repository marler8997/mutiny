Mutiny

A scriptable mod tool for Unity games. Attach it to a game that's already running, then edit your mods while you play. Every save takes effect on the next frame. No restart, no rebuild.

Download MutinySetup.exe

Windows. Installs to your user profile, no admin needed. Source on GitHub.

How it works

AttachOpen Mutiny while a Unity game is running and click Attach. Or launch the game from Mutiny.
Write a modSave a script into the game's mods folder. It runs on the next frame.
Edit while playingChange the file, alt-tab back. The new version is already running.

A panel inside the game lists your mods with their status, and each has a checkbox to turn it off and on.

What a mod looks like

A mod runs from the top on every frame. This one keeps the player's stamina full in PEAK:

// %LOCALAPPDATA%\mutiny\app\PEAK\mods\stamina
@Section(.update)
var game = @Assembly("Assembly-CSharp")
var Character = @Class(game.Character)
if (Character.get_localCharacterExists() == 0) { @Exit("no character") }
var me = Character.localCharacter
me.data.set_currentStamina(me.GetMaxStamina())

The script talks to the game's own classes and methods, the same ones a C# mod would use, without a compiler or a game restart between edits. @Exit ends the frame's run and its text is the mod's status in the panel.

Works with

  • Unity games on Windows, both scripting backends: Mono and IL2CPP.
  • Games that are already running. Mutiny attaches to the process; it never touches the game's files.
  • Scripts and AI agents, through the mutiny command line and a language reference written for them.

Not for games with anti-cheat. Attaching to one is the kind of thing anti-cheat exists to stop, and online play with mods is against most games' rules anyway.
